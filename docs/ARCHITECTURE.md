# Архитектура

> Описывает код, который есть в репозитории (версия 0.1, 2026-11-09). Что не проверено на
> реальном железе — в разделе «Что не проверено».

## Стек

- **Rust** — всё приложение.
- **[Rune](https://github.com/anomalyco/rune)** — нативный UI-фреймворк на Rust с GPU-рендерингом,
  своей вёрсткой и пружинными анимациями. Работает на macOS, Windows, Linux и в вебе.
  Приложение можно запускать headless: рендерить PNG, выгружать дерево элементов и подавать
  скриптовый ввод. Это удобно для тестов UI и для работы агентов.
  - ⚠️ Rune — **pre-release**: нет версий и релизов. **Решение (2026-11-09):** используем Rune и
    пиним конкретную git-ревизию ветки `dev`; обновляем ревизию осознанно, отдельным изменением.
    UI держим тонким слоем над логикой, чтобы смена фреймворка не задела ядро.
  - Rune не занимается звуком. Аудио — отдельный слой (ниже).

## Главный принцип: логика отдельно от звука и UI

Из `AGENTS.md`: «Keep puzzle logic separate from rendering and input». Применяем шире: вся
музыкальная и адаптивная логика живёт в чистых крейтах без звука и UI и тестируется обычными
`cargo test`.

## Крейты (Cargo workspace)

```
crates/
  aa-core/       модель данных: Project, Track, Clip, Pattern, Note, Instrument, Scale… + сериализация
  aa-theory/     музыкальная теория: лады, аккорды, евклидовы ритмы, вариации мотива (чистые функции)
  aa-adaptive/   адаптивный движок: параметры, сглаживание, кривые, режимы, переходы (детерминирован)
  aa-puzzle/     ритмические головоломки Timing / Pattern / Echo: паттерны, проверка ввода, допуски
  aa-engine/     реалтайм-аудио: транспорт, планировщик, синт, сэмплер, микшер, эффекты
  aa-midi/       MIDI in/out, MIDI Clock, список устройств
  aa-capture/    запись со входа: автосэмплинг железа, петля под MIDI Clock, свободная запись; калибровка задержки
  aa-export/     экспорт в FMOD: рендер стемов, manifest.json, головоломки и эталонные тесты к ним
  aa-assistant/  AI-ассистент: Claude, Codex (OpenAI) и Qwen по API через curl, предложения правок с Undo
apps/
  adaptaudio/    приложение на Rune: экраны, ввод, анимации; `devices.rs` следит за MIDI- и аудиоустройствами
                 в фоне, `library.rs` хранит библиотеку звуков, `update.rs` обновляет приложение из GitHub Releases
tools/
  fmod-import/   JavaScript-скрипт для FMOD Studio: читает manifest.json и собирает события
  bundle-macos/  сборка Adaptaudio.app и zip для релиза
```

Зависимости между крейтами (стрелка: «использует»):

```
adaptaudio  ──► aa-engine ──► aa-adaptive ──► aa-core
     │              │             aa-theory ──► aa-core
     │              └──► aa-midi
     ├──► aa-capture ──► aa-midi
     ├──► aa-export  ──► aa-engine (офлайн-рендер), aa-adaptive, aa-puzzle
     └──► aa-puzzle  ──► aa-core
```

`aa-engine` нужен только самому Adaptaudio: чтобы слушать музыку и рендерить стемы. В игре
звук играет FMOD (см. «Связь с игрой»).

## Потоки

| Поток                              | Что делает                                    | Правила                                                              |
|------------------------------------|-----------------------------------------------|----------------------------------------------------------------------|
| **UI** (Rune)                      | Экраны, ввод, анимации                        | Никогда не трогает аудио напрямую, только шлёт команды               |
| **Аудио** (callback аудиодрайвера) | Генерирует звук блоками по N сэмплов          | **Без аллокаций, блокировок, I/O и логов.** Только lock-free очереди |
| **MIDI**                           | Отправка и приём MIDI, Clock                  | Время событий в сэмплах, а не в мс «на глаз»                         |
| **Worker**                         | Загрузка сэмплов, сохранение, Capture, анализ | Готовые данные передаёт в аудиопоток по указателю                    |

Связь UI ↔ аудио:

- UI → аудио: **команды** через lock-free кольцевой буфер (`SetParam`, `LaunchClip`, `SetGameMode`…).
- Аудио → UI: **снимок состояния** (позиция транспорта, уровни, активные слои) через тройной
  буфер. UI читает его каждый кадр для анимаций «в такт».

## Время

- Транспорт: BPM, размер (4/4…), позиция `bar:beat:tick`, **960 PPQ** (тиков на четверть).
- Все события планируются с точностью до сэмпла внутри аудиоблока.
- Квантование переходов считается от позиции транспорта, а не от системного времени.

## Модель данных (aa-core)

```
Project
├── settings: tempo, time_signature, key, scale
├── tracks: [Track]
│   ├── role: Pad | Bass | Kick | Snare | Hats | Perc | Lead | Arp | Ambience | Fx | Custom
│   ├── instrument: Synth(Patch) | Sampler(SampleSet) | External(MidiPort, channel)
│   ├── clips: [Clip]  (= последовательности из AGENTS.md)
│   │   └── pattern: steps/notes (pitch, velocity, length, probability, parameter locks)
│   ├── mixer: volume, pan, sends, effects
│   └── adaptive: influence, response_curves: [Curve(param → target)]
├── sections: [Section]          — наборы клипов по трекам (как «сцены» в Ableton)
├── game_params: [ParamDef]      — name, default, slew
├── game_modes: [GameModeDef]    — section, параметры по умолчанию, цвет
├── transitions: [TransitionRule]
├── events: [EventDef → Stinger]
├── scenarios: [Scenario]        — сценарии для Playtest
└── puzzles: [PuzzlePattern]
```

Каждая нота может переопределить параметры звука (parameter lock, как у Elektron). Так
«каждый звук в каждой последовательности» настраивается отдельно.

### Встроенный синт («simple wave generator»)

Минимум для старта (субтрактивный синтез):

- 2 осциллятора: sine, saw, square/pulse, triangle, noise; расстройка и октава;
- ADSR на громкость, ADSR на фильтр;
- фильтр LP/HP/BP: cutoff, resonance;
- 1–2 LFO;
- Pitch envelope (нужна для бочки: «синус, падающий по высоте» = kick).

Пресеты по ролям: Kick, Snare (шум + тон), Hats (шум + HP), Bass, Pad, Lead, Arp.

## Формат проекта

Проект — папка, удобная для git:

```
CedarStation.aaproj/
  project.json       вся модель, включая сценарии Playtest; человекочитаемый текст
  samples/           WAV (сэмплы Capture, полевые записи, окарина…)
```

- `project.json` пишется атомарно (временный файл + переименование).
- Автосохранение (по умолчанию раз в минуту, если у проекта есть папка).
- Undo: снимок проекта перед каждым изменением (до 200 шагов); перетаскивание — один шаг.
  Предложения AI-ассистента применяются тем же путём.
- В файле проекта есть `format_version` и место для миграций (`aa_core::io::migrate`).
- Настройки приложения (не проекта) — `~/Library/Application Support/Adaptaudio/settings.json`;
  ключ API — в Keychain (`adaptaudio-anthropic`).

## Связь с игрой

**Решение (2026-11-09):** Cedar Station делается на **Unity**, звук в игре играет **FMOD**.
**Свой нативный плагин не нужен.**

### Почему без плагина

FMOD уже умеет всё, что нужно адаптивной музыке во время игры:

- параметры (непрерывные, дискретные, с метками) и автоматизацию по ним;
- переходы между частями таймлайна с квантованием по такту или доле;
- мульти-инструменты со случайным выбором и вероятностью срабатывания;
- эффекты и снапшоты;
- колбэки бита и маркеров в Unity;
- Live Update: подключиться к запущенной игре и крутить микс на лету.

Свой плеер повторял бы FMOD, и звук пришлось бы поддерживать в двух местах. Поэтому
Adaptaudio — инструмент **сочинения и прототипирования**, а FMOD — **рантайм**.

| Задача | Adaptaudio | FMOD Studio | Unity |
|---|---|---|---|
| Сочинение, звук, Capture с железа | ✅ | | |
| Прототип адаптивности (Playtest) | ✅ | | |
| Сборка событий, финальный микс | | ✅ | |
| Проигрывание в игре | | ✅ | вызывает FMOD API |
| Тонкая настройка в запущенной игре | | ✅ Live Update | |
| Головоломки: данные | ✅ `aa-puzzle` (экран Puzzle Lab убран из UI) | | читает `puzzles.json` |
| Головоломки: проверка ввода | эталон на Rust | | C#-модуль по данным |

### Конвейер

```
Adaptaudio ── Export ──► Export/<scene>/
                            stems/*.wav           стемы: трек × раздел, ровно N тактов
                            manifest.json         темп, размер, разделы, лупы, кривые, переходы, маркеры
                            puzzles.json          головоломки Timing / Pattern / Echo
                            puzzle_vectors.json   эталон: входы → ожидаемые результаты
            ── tools/fmod-import ──► FMOD Studio  скрипт создаёт или обновляет событие
            ── Build ──► FMOD banks ──► Unity (FMOD for Unity)
```

1. **Стемы.** `aa-engine` рендерит каждый трек каждого раздела в WAV офлайн. Длина — ровно N
   тактов. Чтобы луп не щёлкал на стыке, рендерим луп дважды и берём второй проход: хвосты
   реверба и дилея из конца уже «заходят» в начало.
2. **Manifest.** Описание всего, что переносится в FMOD. Соответствие понятий — в
   [ADAPTIVE_AUDIO.md](ADAPTIVE_AUDIO.md#как-это-ложится-на-fmod).
3. **Импорт в FMOD Studio.** У FMOD Studio есть скриптовый API на JavaScript. Скрипт
   `tools/fmod-import` читает `manifest.json` и собирает событие: треки, инструменты, параметры,
   автоматизацию, переходы, маркеры. Начать можно вручную (перетащить стемы и настроить событие
   по manifest), а автоматизировать, когда структура устоится.
   ❓ Проверить на твоей версии FMOD Studio, что скрипт умеет создавать автоматизацию и
   transition regions.
4. **Unity → FMOD.** Игра управляет музыкой только через FMOD:
   - `EventInstance.setParameterByName("Intensity", 0.7f)` — локальный параметр события,
     или `RuntimeManager.StudioSystem.setParameterByName(...)` — глобальный параметр;
   - режим игры — параметр с метками `Mode` (Explore, Stealth…);
   - события игры — стингеры: отдельные one-shot события или переходы внутри музыкального события.
5. **Бит для головоломок.** Музыкальное событие подписывается на колбэки FMOD `TIMELINE_BEAT` и
   `TIMELINE_MARKER`. Колбэк приходит не в главном потоке Unity, поэтому его кладут в очередь.
   Для точной оценки ввода берём позицию таймлайна (`getTimelinePosition`) и темп из manifest.
   Задержку ввода и звука игрок калибрует в настройках, как в любой ритм-игре.
6. **Головоломки в Unity.** Проверка ввода — небольшой C#-модуль, который читает `puzzles.json`.
   Чтобы Rust (`aa-puzzle`) и C# (игра) не разошлись, C#-тесты прогоняют `puzzle_vectors.json`.
   Логика головоломок отделена от рендеринга и ввода с обеих сторон, как требует `AGENTS.md`.

### Что теряется без плагина и как это обойти

| Возможность Adaptaudio | Как перенести в FMOD |
|---|---|
| Вероятность каждой ноты (плотность) | Рендерить варианты плотности отдельными стемами (`hats_8th`, `hats_16th`) и смешивать по Intensity. Для случайности — мульти-инструмент с шансом срабатывания |
| Встроенный синт, parameter locks, звук железа | Запекаются в стемы |
| PuzzleStep как нота в ладу | Мульти-инструмент или programmer instrument с нотами лада; ноту выбирает игра |
| Paranoia: детюн, «плывущая плёнка» | Эффекты FMOD (pitch shifter, chorus/flanger, tremolo) с автоматизацией по параметру |
| Сдвиг бита при Paranoia | Логика игры: C#-модуль головоломки смещает окна допуска |
| Совпадение звука Adaptaudio и игры | Статичные эффекты запекать в стемы; эффекты, которые зависят от параметров, проверять в FMOD |

**Правило:** всё, что есть в Adaptaudio, либо экспортируется в FMOD, либо помечено в UI значком
«только прототип». Так нельзя случайно насочинять то, что не перенесётся в игру.

**Когда плагин может вернуться.** Если понадобится по-настоящему генеративная музыка (ноты
рождаются прямо в игре), у FMOD есть API для своих DSP- и instrument-плагинов на C. Туда можно
поставить `aa-engine`. Сейчас это не нужно.

## Зависимости

Добавлены 2026-11-09 (решение принято в режиме автономной работы по просьбе владельца).

| Крейт | Где | Зачем |
|---|---|---|
| `rune` (git rev `d751f07`) | `apps/adaptaudio` | UI |
| `cpal` 0.15 | `aa-engine`, `aa-capture` | Аудиовывод и аудиоввод (CoreAudio) |
| `midir` 0.10 | `aa-midi` | MIDI in/out |
| `rtrb` 0.3 | `aa-engine`, `aa-midi`, `aa-capture` | Lock-free кольца между потоками |
| `hound` 3.5 | `aa-engine`, `aa-capture`, `aa-export` | Чтение и запись WAV |
| `serde` + `serde_json` | везде | Проект, manifest, головоломки, настройки |

HTTP для ассистента — системный `curl` (ключ передаётся через stdin, не через аргументы).
DSP (осцилляторы, фильтр, ADSR, реверб) написан с нуля в `aa-engine/src/dsp.rs` и `reverb.rs`.

Состояние аудио для UI — атомики `aa_engine::Telemetry`; поток `adaptaudio-live` 60 раз в
секунду копирует их в `rune::Live` (метры, плейхеды, пульс бита, сфера XY-пада). Без
аудиоустройства (и в headless-режиме) движок крутится в UI-потоке вхолостую, так что интерфейс
живой и снимки экрана честные.

## Тестирование

- `aa-core`, `aa-theory`, `aa-adaptive`, `aa-puzzle`: обычные unit-тесты, детерминированные.
- `aa-engine`: **офлайн-рендер**. Движок рендерит N секунд в буфер без аудиоустройства, а тест
  проверяет: тишина там, где должна быть; переход случился на границе такта; пиков > 0 dBFS нет.
- UI: headless-режим Rune — скриншоты и дерево элементов.
- Сценарии Playtest можно гонять как тесты: «после Detected Kick громче −12 dB в пределах 1 такта».
- `aa-export`: длина стема ровно N тактов в сэмплах, стык лупа без скачка, manifest проходит
  проверку схемы, `puzzle_vectors.json` совпадает с поведением `aa-puzzle`.

- Приложение: headless-тесты в `apps/adaptaudio/src/tests.rs` нажимают настоящие кнопки
  (`Runtime::find` + `pointer_down/up`) с движком в офлайн-режиме.

## Что не проверено

- **Железо:** 2026-11-09 проверено на реальных устройствах только одно: нота по MIDI в Hydrasynth
  возвращается на вход 2 Scarlett Solo с задержкой около 13,5 мс. Полный Capture, запись петли
  с EP-1320 и свободная запись с реальным железом не запускались. Автообновление не проверялось
  на настоящем релизе. Перечисление аудиовходов на этом Mac блокируется, пока macOS ждёт
  разрешения на микрофон: поэтому оно идёт в фоне с таймаутом 5 с.
- **FMOD:** скрипт `tools/fmod-import` проверен только на заглушке API; 27 мест помечены `VERIFY:`.
- **AI-ассистент:** реальный API не вызывался (нет ключа); формат запросов проверен тестами с
  поддельным транспортом.
- **Unity:** C#-порт проверки головоломок не написан; для него есть `puzzle_vectors.json`.

# Импорт сцены Adaptaudio в FMOD Studio

В Cedar Station музыку играет FMOD. Adaptaudio сочиняет и прототипирует, а потом **экспортирует**
сцену: стемы (WAV) и `manifest.json` с описанием всего остального. Скрипт
`import_adaptaudio.js` читает manifest и собирает из него музыкальное событие в FMOD Studio.

Общая схема — в [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md#связь-с-игрой), соответствие
понятий — в [docs/ADAPTIVE_AUDIO.md](../../docs/ADAPTIVE_AUDIO.md#как-это-ложится-на-fmod).

> ⚠️ **Честно:** скрипт написан без доступа к FMOD Studio. Все места, где автор не уверен в
> скриптовом API, помечены в коде `// VERIFY:`. Если шаг не получился, скрипт не падает, а
> записывает его в список «сделать руками». Первый запуск — это проверка, а не готовый результат.

## Словарик

| Слово | Что это |
|---|---|
| **Стем** | WAV одного трека в одном разделе, ровно на длину раздела. Луп: конец сшит с началом |
| **Событие (event)** | «Звуковой объект» FMOD, который запускает игра. Вся музыка сцены — одно событие |
| **Таймлайн** | Горизонтальная лента события. Разделы лежат на ней друг за другом |
| **Loop region** | Отрезок таймлайна, который повторяется по кругу (один раздел) |
| **Destination marker** | Метка «сюда можно прыгнуть». По одной на каждый режим игры |
| **Transition region** | Отрезок, внутри которого FMOD прыгает к метке, когда выполнено условие (`Mode = Chase`) |
| **Квантование** | Прыжок не сразу, а на ближайшей доле или такте, чтобы не сбить ритм |
| **Параметр** | Число, которое игра меняет: `Intensity`, `Tension`… и `Mode` (режим с метками) |
| **Seek speed** | С какой скоростью параметр доезжает до нового значения (единиц в секунду) |
| **Стингер** | Короткий разовый звук на событие игры (Detected, PuzzleSolved) |

## Шаг 1. Экспорт из Adaptaudio

1. Откройте проект и проверьте его в Simulator: всё ли звучит, как задумано.
2. Сделайте экспорт сцены (функция `aa_export::export_scene`; кнопка в приложении появится, когда
   её подключат к движку). Настройки по умолчанию: 48 кГц, 24 бит, луп рендерится дважды,
   стингеры включены, хвост стингера 2 с.
3. Получится папка `Export/<сцена>/`:

   ```text
   stems/Explore__Pad.wav      раздел__трек.wav — луп ровно на длину раздела
   stems/stinger__Detected.wav стингер: клип + 2 с хвоста
   manifest.json               параметры, регионы, треки, автоматизация, переходы, события
   puzzles.json                головоломки для C#-модуля в Unity
   puzzle_vectors.json         эталонные входы и ответы для C#-тестов
   README.txt                  краткая памятка + список предупреждений именно этой сцены
   ```

4. Откройте `README.txt` в этой папке и прочитайте раздел предупреждений. Там перечислено всё,
   что **не переносится** в FMOD (например, вероятность нот, сценарии Simulator, External MIDI —
   его надо сначала записать на экране Capture, иначе стем будет тихим).

Повторный экспорт перезаписывает файлы с теми же именами. Старые стемы, которых больше нет в
manifest, остаются в папке — скрипт их просто не использует.

## Шаг 2. Скопировать папку

Скопируйте папку сцены целиком (вместе с `stems/`) куда угодно рядом с проектом FMOD, например
в `<проект FMOD>/Adaptaudio/<сцена>/`. Скрипт импортирует WAV в проект FMOD сам (FMOD копирует их
в свою папку `Assets`).

## Шаг 3. Установить скрипт (один раз)

1. Рядом с файлом проекта `.fspro` создайте папку `Scripts` (если её нет).
2. Скопируйте туда `tools/fmod-import/import_adaptaudio.js`.
3. В FMOD Studio: **Scripts → Reload**. В меню **Scripts** появится **Adaptaudio → Import scene…**

Если пункт не появился — откройте **Window → Console**: там будет ошибка загрузки скрипта.

## Шаг 4. Запустить импорт

1. На всякий случай сохраните проект FMOD (или закоммитьте его).
2. **Scripts → Adaptaudio → Import scene…**, выберите папку сцены (где лежит `manifest.json`).
3. Скрипт создаст:
   - событие `event:/music/<сцена>`. Если такое уже было, старое **переименовывается** в
     `<сцена>_previous` (ничего не удаляется — удалите сами, когда убедитесь, что новое в порядке);
   - параметры: `Intensity`, `Tension`, `Paranoia`, `PuzzleProgress` (0..1, seek speed =
     1 / slew), `Mode` с метками режимов, `Unlocked_<Событие>` (0/1) для закрытых слоёв;
   - tempo marker в начале (для колбэков `TIMELINE_BEAT`);
   - loop region на каждый раздел и destination marker на каждый режим;
   - audio track на каждый трек, в каждом разделе — один стем, зацикленный;
   - автоматизацию громкости (через эффект Gain, фейдер трека остаётся как в Adaptaudio) и
     эффектов (Lowpass, Distortion, Chorus, Flanger) по параметрам — Influence уже «запечён»;
   - transition regions с условием `Mode = <режим>` и квантованием;
   - отдельные one-shot события стингеров `event:/music/<сцена>_stingers/<Событие>`.
4. В конце появится окно с числом ручных шагов. Полный список — в **Window → Console** и в файле
   `import_log.txt` в папке сцены.

## Шаг 5. Проверить руками

Пройдитесь по `import_log.txt`, раздел **MANUAL STEPS**. Обычно там:

- **Кроссфейды переходов.** Скрипт не строит transition timeline. Для каждого перехода с
  кроссфейдом откройте transition region, добавьте transition timeline и сведите старый раздел
  на нет, а новый — вверх за указанное время (в логе переходы сгруппированы по длине).
- **Стингеры на переходах** (Stealth → Alert и т.п.): либо положите стингер на transition
  timeline, либо пусть игра запускает отдельное событие стингера.
- **Плотность (Hats по Intensity).** FMOD не умеет «прореживать» ноты. Отрендерите редкий и
  плотный вариант стема и сведите их встречной автоматизацией громкости по `Intensity`.
- **Панорама**, **сайдчейн** (компрессор Sidechain на басе и пэде с ключом от бочки), **посыл в
  реверб**, **мастер-шина** (громкость, лимитер) — если скрипт не смог, выставьте по manifest.

И послушайте:

1. Нажмите Play на событии, крутите `Intensity` — бочка почти не слышна до ~0.35 и выходит на полную к 0.6.
2. Поменяйте `Mode` — переход должен случиться на следующем такте (или доле, или фразе).
3. `Unlocked_PuzzleSolved` = 1 — должны вступить колокольчики.
4. Стыки лупов не должны щёлкать (луп рендерится дважды, хвосты реверба уже в начале стема).
5. Сравните на слух с Adaptaudio. Chorus и Flanger — только приближение «детюна» и «плывущей
   плёнки» из Paranoia: подстройте их по ушам.

## Что делает игра (FMOD этого не умеет)

Список для конкретной сцены — в `manifest.json → game_side` и в `README.txt`. Коротко:

- **Гистерезис:** не менять `Mode` чаще, чем `min_dwell_seconds` после перехода.
- **Стингеры по событиям:** запускать one-shot событие на следующей доле или такте (колбэк
  `TIMELINE_BEAT` музыкального события).
- **Открытие слоёв:** по событию `PuzzleSolved` выставить `Unlocked_PuzzleSolved = 1`.
- **Старт сцены:** выставить `Mode` до `start()`; чтобы начать сразу с нужного раздела —
  `setTimelinePosition(start_seconds × 1000)` из `manifest.json → regions`.
- **Головоломки:** C#-модуль читает `puzzles.json`, тесты прогоняют `puzzle_vectors.json`.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Скрипт не виден в меню | Window → Console, ошибка загрузки; проверьте, что файл в `Scripts` и сделан Reload |
| `manifest_version … is not supported` | Обновите скрипт из репозитория Adaptaudio |
| Много ручных шагов с `script failed` | API вашей версии FMOD отличается. Найдите в скрипте ближайший `VERIFY:` и поправьте имя метода или свойства |
| Луп щёлкает на стыке | Экспортируйте снова с `loop_passes` = 2 или больше |
| Стем тихий | Трек на External MIDI: запишите его на экране Capture и экспортируйте снова |
